# 代码结构

DiPlay-Nissan 保持现有 Gradle 模块边界：`mobile` 负责应用变体与打包，`common` 放 Activity、车机集成和界面，`shared` 放 CarPlay 协议、传输、编解码与媒体处理。功能较小、还不能独立编译的部分先按职责分包管理，不为了目录整齐增加 Gradle 模块。

## common 包职责

| 包 | 职责 |
| --- | --- |
| `connection` | 连接默认值、热点/Wi‑Fi 配置读写与校验、启动前置条件决策、跨权限/配对等待保存请求、配对手机读取、开机自动连接协调。返回数据或调用连接回调，不构建页面。 |
| `diagnostics` | 诊断报告内容组装与脱敏；页面负责启动导出、选择目标和展示结果。 |
| `settings` | 设置分类、页面归属、通用设置控件。 |
| `ui.components` | 可复用的卡片、按钮、文本等基础控件。 |
| `ui.pages` | 首页和连接设置页的 View 构建；通过 `Actions` 把点击交回 Activity。 |
| `ui.settings` | 设置分类侧栏、概览摘要/工具卡片、连接状态 Presenter、通用设置卡片和音量控件的 View 构建；页面导航和按钮动作通过回调交回 Activity。 |
| `shared` 模块 | CarPlay 会话、协议、USB/Wi-Fi 传输、音频和视频处理。 |

## 依赖约定

- Activity 管理 Android 生命周期、页面路由、权限弹窗和系统 Activity；它作为组装入口连接页面与业务协调器。
- 页面 Builder 负责布局和状态展示。页面点击应通过回调调用业务入口，不直接启动 CarPlay 会话。
- 连接协调器和数据读取类不引用 View；耗时扫描、蓝牙查询在工作线程执行，再通过回调把结果交给界面。`ConnectionLaunchPolicy` 只返回决策，权限请求、提示、停止旧会话和打开 CarPlay 仍由 Activity 执行。
- 设置页面保存影响会话的选项时继续使用现有的重连提示流程；页面拆分不能绕过用户确认。
- CarPlay 协议和媒体实现留在 `shared`，日产固件适配留在 `common`，避免 UI 依赖协议实现细节。

## 当前迁移状态

首页、连接设置页、设置分类导航、概览摘要与工具卡片、连接状态 Presenter、通用设置控件和音频设置控件已移入 `ui`；自动连接扫描、蓝牙就绪等待、热点/Wi‑Fi 设置读写与校验、启动前置条件决策、异步等待时的请求状态、配对手机合并读取、连接偏好读取已移入 `connection`；诊断报告采集、汇总和脱敏已移入 `diagnostics`。`DiPlayActivity` 负责页面路由、生命周期、连接状态计算、权限和系统弹窗，并通过回调连接 UI 与业务；设置分类内容和部分表单交互仍在 Activity 中，后续按领域分组抽离，避免 UI Builder 直接操作 CarPlay 会话或系统服务。
